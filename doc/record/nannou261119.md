# nannou 0.19 → 0.20 移行メモ

2026/11/19 に nannou 0.20 への移行を完了した（branch: `nannou020`）。

| commit | 内容 |
|---|---|
| 3f47ea5 | objc2 を vendor して暫定的にビルドを通した（移行完了後に削除） |
| a63ed4d | ロゴ用フォントを New York から Newsreader に置き換えた |
| a18b0b8 | JetBrains Mono のファミリー名を太さ・斜体ごとに別名にしたフォントを追加した |
| 9c261fd | nannou を 0.20 に移行した |

## 経緯

- Rust を 1.100.0 に上げたら build が通らなくなった
    - 原因: `objc2 0.3.0-beta.3.patch-leaks.3`（loopian → nannou 0.19 → winit 0.28 → objc2）
    - 新しい rustc でトレイト境界のチェックが厳しくなり、E0277 になる
    - 古いベータ版で、もう保守されていない
- objc2 だけを上げることはできなかった
    - winit 0.28 が `objc2 >=0.3.0-beta.3, <0.3.0-beta.4` に固定している
    - objc2 0.4 以降は API が互換でない
- 暫定対処として objc2 を vendor して修正し、そのうえで nannou 0.20 へ移行した
    - 移行後は objc2 も noise も vendor 不要になり、`vendor/` と `[patch.crates-io]` は削除した

## nannou 0.20 の概要

- 0.19 から長く止まっていたのは、Bevy への作り直しのため
- Bevy 0.19.1 / winit 0.30 の上に作られている
- 見慣れた入口は残っている（皮を被せる方針）
    - `nannou::app(model).update(update).run()`
    - `app.draw()`, `app.time()`, `app.window_rect()`, `app.new_window()`, `app.main_window()`
    - 図形: `ellipse`, `rect`, `line`, `polyline`, `tri`, `no_fill`, `stroke`, `stroke_weight`, `x_y`, `w_h`, `radius`, `start`, `end`, `weight`, `rotate`
    - 数学・乱数・ノイズ: `pt2`, `vec2`, `map_range`, `random_range`, `nannou::noise`
- ただし下の Bevy が透けて見える部分がある

### 「ループの持ち主」が Bevy になる

- 0.19: nannou 自身がメインループを回し、`event` → `update` → `view` を順に呼ぶ。Model は nannou が持つ
- 0.20: Bevy がループを回す。Bevy は多数のシステムを並列実行するエンジンで、nannou はその一つ
    - Model は Bevy のリソース（倉庫）に預けられ、`update` などはそこから借りて呼ばれる
- その結果
    - **Model に `Send + Sync` が必須**
    - `App` にライフタイムが付く（`App<'_, '_>`）。ただし `fn update(app: &App, ...)` と省略して書ける
    - `view` で `Frame` を受け取らない。`draw` に書いておけば Bevy が描画する

## API の主な違い

| 項目 | 0.19 | 0.20 |
|---|---|---|
| update | `fn(&App, &mut Model, Update)` | `fn(&App, &mut Model)` |
| view (window) | `fn(&App, &Model, Frame)` + `draw.to_frame()` | `fn(&App, &Model)` |
| イベント | `.event()` で `Event::WindowEvent { simple: ... }` をまとめて受ける | window builder のコールバック（Loopian は使わず、自前のプラグインで受ける。後述） |
| キー | `Key::LShift`, `Key::Key1`, `Key::Back`, `Key::Return`, `Key::V` | `KeyCode::ShiftLeft`, `KeyCode::Digit1`, `KeyCode::Backspace`, `KeyCode::Enter`, `KeyCode::KeyV` |
| 時間 | `app.time`（フィールド） | `app.time()` |
| 色 | palette の `Srgb<u8>`, `srgb::<u8>()`, `rgba()`, `Rgba`, `LIGHTGRAY` | Bevy の `Srgba`, `Srgba::rgb_u8()`, `Srgba::new()`, `LIGHT_GRAY`。`.rgba()` メソッドは `.srgba()` |
| テキストのフォント | `.font(Font)`（`Font::from_bytes` で作る） | `.font("ファミリー名")`。フォントは Bevy の `Font` として登録する |
| ウィンドウ設定 | `win.set_title()`, `win.set_inner_size_pixels()` | builder の `.title()`。サイズは後述 |
| noise | noise 0.7: `Perlin::new()` | noise 0.9: `Perlin::new(seed)`（`Perlin::DEFAULT_SEED` = 0 で同じ結果） |

## Loopian での対応内容

| 箇所 | 内容 |
|---|---|
| 各 Cargo.toml | `nannou = "0.20.0"`。`loopian_app` にフォント登録用の `bevy = { version = "0.19.1", default-features = false, features = ["bevy_text"] }` を追加 |
| `loopian_app/src/main.rs` | builder を `.update().add_plugin(KeyInputPlugin)` に。`view` から `Frame` / `to_frame` を削除。`app.time()` に。`set_exit_on_escape(false)` は不要（0.20 は Esc で終了しない） |
| Model の Sync 対応 | `ui_hndr` を `Mutex<Receiver<UiMsg>>` に。`GenerativeView` / `NoteObj` / `BeatObj` に `: Send + Sync` を付けた。Sync でないのは Receiver だけだった |
| `loopian_app/src/cmd/input_txt.rs` | `window_event(Event)` を `key_input(KeyInput)` に。`Key::...` を `KeyCode::...` に |
| 色 | `loopian_graphics/*`, `loopian_app/src/graphic/*` の palette の型を Bevy の `Srgba` に |
| フォント | `loopian_graphic_api/src/font.rs` にファミリー名の定数を置き、`Font` 型の代わりに `FontName`（`&'static str`）で持ち回す |
| 不要になったもの | objc2 / noise の vendor と `[patch.crates-io]`、未使用の依存（`device_query`, `loopian_graphics` の `rand` / `rand_distr`）、workspace の `license` |

## 移行で見つかった落とし穴

### 1. received_character がキーを離したときにも文字を渡す

- nannou 0.20 の `received_character` は Bevy の `KeyboardInput` から作られているが、押した/離したを区別していない
    - そのまま使うと、1回のキー入力で文字が2回入る
- また Space は `Key::Character` ではないため、`received_character` には来ない
- 対処: nannou のキー関係のコールバックは使わず、Bevy の `KeyboardInput` を直接受け取る `KeyInputPlugin` を `main.rs` に作った
    - `PreUpdate` のシステムで `KeyboardInput` を読み、`KeyInput::Pressed(KeyCode, Option<String>)` / `KeyInput::Released(KeyCode)` として static のキューに積む
    - 文字は押したときの `text` から取る（Space も `" "` として来る）
    - `update` の最初にキューを取り出し、起きた順番どおりに `InputText::key_input()` に渡す
    - `key_input()` は、押したキーの処理 → そのキーで入力された文字の処理、の順（0.19 の KeyPressed → ReceivedCharacter と同じ順）
- キーリピートも「押した」として来るので、Backspace や矢印キーの押しっぱなしは 0.19 と同じく動く
- `KeyCode` は物理キーの位置。Ctrl + V や Ctrl + 数字は位置で判定するが、JIS キーボードでも同じ位置なので問題ない
- IME（日本語入力）がオンのときの入力は別の仕組み（`Ime` イベント）で来るため、受け取れない。英数入力で使う前提

### 2. サイズ指定のないテキストの枠が変わった

- `draw.text()` で `w_h` を指定しないときの枠
    - 0.19: 200 × 200
    - 0.20: window 全体の大きさ
- 左寄せのテキストは枠の左端に揃うため、0.20 では window 幅の半分だけ左にずれた（スクロールテキストが画面外にはみ出した）
- 対処: サイズ指定のない `draw.text()` すべてに、0.19 と同じ `.w_h(200.0, 200.0)` を明示した（5か所）

### 3. window サイズが pixel 指定どおりにならない

- builder の `.size_pixels()` は、window を作る前の時点では拡大率（Retina では 2）が分からず、1 として扱われる
    - その結果、pixel 数がそのまま point として扱われ、Retina では2倍の大きさで開こうとし、画面サイズに切り詰められた
- 対処: builder ではサイズを指定せず、`update` の `adjust_window_size()` で合わせる
    - 拡大率を読み取り、「指定 pixel ÷ 拡大率」の point で `set_size_points()` する
    - 拡大率は1フレーム目は 1、2フレーム目で確定するので、実際の pixel 数が設定値になるまで（最大60フレーム）繰り返す
    - 起動直後の1〜2フレームだけ違う大きさで表示されてから、指定サイズになる

### 4. フォントの太さ・斜体を指定できない

- 0.20 のテキストはファミリー名しか指定できず、太さ・斜体を指定する手段がない
- フォントライブラリ fontique は name テーブルの 16番（Typographic Family）を優先し、なければ 1番（Family）を使う
- 元の JetBrains Mono は4つとも 16番が `JetBrains Mono` で区別できなかった
- 対処: fontTools（Python）で 1番と 16番をファイルごとに別の名前に書き換え、`*-Loopian.ttf` として保存した
    - 0番（著作権）と 13番（ライセンス）は残してある

| 定数 | ファイル | ファミリー名 | 用途 |
|---|---|---|---|
| FONT_NRM | JetBrainsMono-ExtraLight-Loopian.ttf | JetBrains Mono ExtraLight | スクロールテキスト（入力行）、日付、graphic pattern |
| FONT_ITALIC | JetBrainsMono-ExtraLightItalic-Loopian.ttf | JetBrains Mono ExtraLight Italic | スクロールテキスト（返答行） |
| FONT_BOLD | JetBrainsMono-SemiBold-Loopian.ttf | JetBrains Mono SemiBold | インジケータ、入力欄 |
| FONT_TITLE | JetBrainsMono-ExtraBold-Loopian.ttf | JetBrains Mono ExtraBold | タイトル・サブタイトル |
| FONT_SERIF | Newsreader16pt-Regular.ttf | Newsreader 16pt | ロゴ（Loopian / by Kigakudoh / Ver.） |

- フォントの登録
    - nannou は Bevy の `Font` 型を再公開していないので、`bevy` を直接依存に追加した
    - 実行ファイルの場所から `assets` フォルダを探し（0.19 の `assets_path()` と同じ探し方）、バイト列を読んで `app.asset_server().add(Font::from_bytes(...))` で登録する
    - 返ってくる `Handle<Font>` は `Graphic` に保持しておく（手放すと登録が消える）
- 文字幅が 0.19 と少し違うため、ロゴの「Loopian」「by Kigakudoh」の位置を調整した

## フォントのライセンス

- JetBrains Mono: SIL OFL 1.1
    - Reserved Font Name の宣言はないので、名前を変えて配布してよい
    - 著作権表示とライセンスを添える → `assets/fonts/OFL-JetBrainsMono.txt`
    - 改変版の宣伝に JetBrains の名前を使わない
    - 改変版も OFL のまま配布する
- Newsreader: SIL OFL 1.1（Reserved Font Name なし） → `assets/fonts/OFL-Newsreader.txt`
- New York は Apple のライセンスで再配布できないため、Newsreader に置き換えて削除した
- 元の `JetBrainsMono-*.ttf`（`-Loopian` の付かないもの）は読み込まなくなったので、`assets/fonts/` と `Loopian_Release/assets/fonts/` から削除した。作り直すときは git の履歴か JetBrains Mono の配布元から取り出す
